# Family Expense Tracker — Implementation Plan

## Context

Build a custom family expense tracking application for personal/family use. The app must support **web** (desktop/laptop) and **mobile** (Android) — the mobile app is an Android WebView wrapper that loads the mobile-responsive web app. The primary goal is **ultra-low-friction expense entry** that even elder family members can use comfortably. The app includes full analytics/dashboard capabilities for understanding spending patterns across family members, categories, time periods, and payment methods.

**Key constraint**: Plan is broken into 28 small sequential steps so a smaller model (Sonnet) can execute one step at a time.

## Auth System

- **Super Admin**: username from env var `SUPER_ADMIN_USERNAME`, password from env var `SUPER_ADMIN_PASSWORD`
- Super admin creates **families**, each with a **family owner**
- Family owner creates **family members** with userid + PIN (4-6 digit)
- Family owner shares PIN orally with members
- All users authenticate via `POST /api/auth/login` (username + password/PIN) → JWT (**15-day expiry**)
- Roles: `super_admin`, `family_owner`, `family_member`

## Database Schema

```sql
CREATE TABLE users (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    username TEXT NOT NULL UNIQUE,
    password_hash TEXT NOT NULL,
    display_name TEXT NOT NULL,
    role TEXT NOT NULL CHECK(role IN ('super_admin', 'family_owner', 'family_member')),
    family_id INTEGER,
    is_active INTEGER NOT NULL DEFAULT 1,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (family_id) REFERENCES families(id) ON DELETE CASCADE
);

CREATE TABLE families (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL,
    created_by INTEGER NOT NULL,
    owner_id INTEGER,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (created_by) REFERENCES users(id),
    FOREIGN KEY (owner_id) REFERENCES users(id)
);

CREATE TABLE tags (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL,
    icon TEXT,
    family_id INTEGER,  -- NULL = global/pre-built
    is_active INTEGER NOT NULL DEFAULT 1,
    sort_order INTEGER DEFAULT 0,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (family_id) REFERENCES families(id) ON DELETE CASCADE
);
CREATE UNIQUE INDEX idx_tags_family_name ON tags(family_id, name);

CREATE TABLE expenses (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    family_id INTEGER NOT NULL,
    user_id INTEGER NOT NULL,
    amount REAL NOT NULL,
    tag_id INTEGER NOT NULL,
    payment_method TEXT NOT NULL CHECK(payment_method IN ('cash', 'online', 'upi', 'card')),
    note TEXT,
    expense_date DATE NOT NULL,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (family_id) REFERENCES families(id) ON DELETE CASCADE,
    FOREIGN KEY (user_id) REFERENCES users(id),
    FOREIGN KEY (tag_id) REFERENCES tags(id)
);
CREATE INDEX idx_expenses_family_date ON expenses(family_id, expense_date);
CREATE INDEX idx_expenses_family_user ON expenses(family_id, user_id);
CREATE INDEX idx_expenses_family_tag ON expenses(family_id, tag_id);

CREATE TABLE user_tag_frequency (
    user_id INTEGER NOT NULL,
    tag_id INTEGER NOT NULL,
    usage_count INTEGER NOT NULL DEFAULT 0,
    last_used_at DATETIME,
    PRIMARY KEY (user_id, tag_id),
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE,
    FOREIGN KEY (tag_id) REFERENCES tags(id) ON DELETE CASCADE
);
```

## API Endpoints

### Auth
| Method | Path | Auth | Description |
|--------|------|------|-------------|
| POST | `/api/auth/login` | None | Login (username + password/PIN) → JWT |
| GET | `/api/auth/me` | JWT | Current user info |

### Super Admin
| POST | `/api/admin/families` | SuperAdmin | Create family + owner |
| GET | `/api/admin/families` | SuperAdmin | List all families |
| DELETE | `/api/admin/families/:id` | SuperAdmin | Delete family |

### Family
| GET | `/api/family` | Owner/Member | Own family details |
| GET | `/api/family/members` | Owner/Member | List members |
| POST | `/api/family/members` | Owner | Add member (userid + PIN) |
| PUT | `/api/family/members/:id` | Owner | Update member |
| DELETE | `/api/family/members/:id` | Owner | Deactivate member |

### Tags
| GET | `/api/tags` | Any | All tags (global + family custom) |
| GET | `/api/tags/suggested` | Any | User's frequent tags (top 10) |
| POST | `/api/tags` | Owner | Create custom family tag |

### Expenses
| POST | `/api/expenses` | Any | Add expense |
| GET | `/api/expenses` | Any | List (paginated, filterable by user/tag/payment/date) |
| GET | `/api/expenses/recent` | Any | Last 20 expenses |
| PUT | `/api/expenses/:id` | Creator/Owner | Update |
| DELETE | `/api/expenses/:id` | Creator/Owner | Delete |
| GET | `/api/expenses/export` | Any | Export to Excel (.xlsx) with same filters as list |

### Analytics
| GET | `/api/analytics/summary?range=today\|week\|month\|custom&from=&to=` | Any | Total spent |
| GET | `/api/analytics/by-person?range=...` | Any | Per-person breakdown |
| GET | `/api/analytics/by-category?range=...` | Any | Per-category breakdown |
| GET | `/api/analytics/by-payment-method?range=...` | Any | Per-payment-method breakdown |
| GET | `/api/analytics/daily-trend?month=YYYY-MM` | Any | Daily totals for a month |
| GET | `/api/analytics/monthly-comparison` | Any | This month vs last month |

*"Any" = any authenticated family member. family_id always derived from JWT.*

**Step 14: Weekly database backup to Gmail**
- Create `internal/service/backup_service.go`
- Uses Go's built-in `time.Ticker` goroutine — runs weekly (configurable via `BACKUP_INTERVAL` env, default `168h`)
- Backup process:
  1. Copy SQLite DB file using SQLite's online backup API (`sqlite3_backup`) for safe, consistent snapshots
  2. Gzip compress the copy (e.g., `expense-tracker-backup-2026-04-14.db.gz`)
  3. Send as email attachment via Gmail SMTP (`smtp.gmail.com:587` with TLS)
  4. Env vars: `BACKUP_EMAIL_TO`, `BACKUP_SMTP_USER`, `BACKUP_SMTP_PASSWORD` (Gmail App Password)
  5. After sending, keep local copy in `backups/` directory
  6. Auto-delete local backups older than 2 months
- Also runs a cleanup on the `backups/` folder at startup
- Add `net/smtp` (stdlib) + `compress/gzip` (stdlib) — no extra dependencies
- Makefile target: `make backup` for manual trigger
- Also add `POST /api/admin/backup` (super admin only) to trigger backup from UI
- *Test*: set short interval, verify email received with .db.gz attachment, verify old backups are cleaned up

## Hosting Architecture

The **Go binary serves everything** — both the API (`/api/*`) and the React frontend (all other routes). The React build output is embedded into the Go binary at compile time using Go's `embed.FS`. This means:

- **Single binary deployment**: one file + one SQLite database = complete app
- **No separate web server** (no Nginx, no Apache, no Node.js server)
- **Docker image** is minimal Alpine Linux + the binary
- **The WebView mobile app** simply points to wherever this binary is hosted (e.g., `http://your-server:8080`)
- For local development, Vite dev server proxies `/api` calls to the Go backend

---

## Weekly Database Backup System (Gmail)

The Go binary includes a built-in backup scheduler:

1. **Trigger**: Runs automatically every 7 days (configurable via `BACKUP_INTERVAL` env var). Can also be triggered manually via `POST /api/admin/backup` or `make backup`
2. **Process**: SQLite online backup API → gzip compress → email as attachment
3. **Delivery**: Sent via Gmail SMTP (`smtp.gmail.com:587` with TLS) to `BACKUP_EMAIL_TO`
4. **Gmail App Password**: Required since Gmail blocks less-secure apps. Generate at Google Account → Security → App Passwords
5. **Local retention**: Backups saved in `backups/` directory, auto-deleted after 2 months
6. **Env vars needed**: `BACKUP_EMAIL_TO`, `BACKUP_SMTP_USER`, `BACKUP_SMTP_PASSWORD`
7. **Email subject**: `[ExpenseTracker] Weekly Backup - 2026-04-14`
8. **Attachment**: `expense-tracker-backup-2026-04-14.db.gz` (~small file, SQLite compresses well)

2. **Frontend**: `cd frontend && npm run dev` → test all pages in browser (mobile viewport)
3. **Full build**: `make build` → single binary serves everything (API + React frontend from same port)
4. **Docker**: `docker-compose up --build` → app works at :8080
5. **E2E flow**: Super admin login → create family → owner login → add members → member login → add expenses → view dashboard → verify analytics
6. **Excel export**: Filter expenses → click Export → verify .xlsx downloads and opens correctly
7. **Backup**: Configure Gmail env vars → trigger manual backup via `make backup` or admin API → verify email received with .db.gz attachment
8. **Mobile**: Build APK → install on Android → verify all features work in WebView
